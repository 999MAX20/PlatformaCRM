## Исправление

Аудит воспроизвёл создание Appointment для одноимённого клиента с другим телефоном.
В `voice_schedule_planner.py` отсутствие совпадения по указанному телефону больше
не разрешает выбрать единственное совпадение по имени. Ответ RU/KK/EN объясняет
конфликт и предлагает явно выбрать доступного клиента либо уточнить имя/телефон.
До выбора нет клиента, посещения, плана или proposal; ранее сообщённые детали
сохраняются. Выбор ID из уточнения разрешает посещение, но не меняет телефон клиента.

`voice_schedule_commands.py` повторяет проверку для name/phone payload при
исполнении; неподходящий телефон вызывает validation error и не оставляет частичных
данных. Общая `normalize_phone` сохраняет принятые правила формата, включая 8/+7.
Нестрочное значение телефона отклоняется. Права, tenant, approval, audit, replay и
доменные события/уведомления сохраняются. Новых схем, миграций, прав и UI-настроек нет.

## Очередь и оставшаяся граница

`output/voice-identity-20261111/queue_probe.py` проверяет отдельный Redis, Celery solo
в дочерних процессах и PostgreSQL17 в одноразовом кластере. Модель заменена
детерминированным fixture; внешняя сеть запрещена. Рабочие сервисы не останавливаются.
Сценарии: отправка при отсутствующем worker, потерянный HTTP-ответ, duplicate delivery;
принудительное завершение worker во время provider preparation, истечение lease и
явный retry; завершение после commit до ACK, повтор доставки без новых записей.
Истечение lease ускоряется только timestamp fixture; повтор доставки после ACK-crash
направляется явно и не заявляется как проверка штатного visibility timeout.
Все три сценария очереди PASS, процесс завершился с exit0. Проверены реальные
процессы Celery и отдельный Redis, а не memory broker. После успешного retry и
после commit-before-ACK сохранены ровно три Task и три ApprovalRequest для трёх
команд; повторные delivery/HTTP не увеличили эти числа или число вызовов fixture.
В той же одноразовой PostgreSQL среде9 identity и3 реальные concurrency проверки
прошли: **12 PASS**. System check PASS. `queue-result.json`, `queue.log`,
`worker-initial.log`, `worker-recovery.log`, `worker-after-commit.log` содержат
доказательства. Все собственные worker/Redis/PostgreSQL остановлены; disposable
среда удалена после завершения. Рабочие задания/сервисы не менялись.

Первый запуск harness остановился из-за имени `queue.py`, перекрывавшего стандартный
модуль Python; переименован в `queue_probe.py`. Это ошибка проверочного сценария,
не приложения. Начальный журнал сохранён, инфраструктура остановлена в finally.

Остаток кода исправления и выбранной локальной queue-приёмки отсутствует.
