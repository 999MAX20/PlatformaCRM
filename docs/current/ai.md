# AI: действующие полномочия и защита

Статус: **действующий контракт**. Срез 07.10.2026, `f01d226`.
Последние решения: controlled creation 02.10, назначение/изоляция/удаление 05.10,
память/действия 06.10, customer safety и пауза CRM-аналитики 07.10.
Пользовательский сценарий и проверенные границы —
[паспорт клиентского агента](../pre-production/customer-ai-agent.md).

## Назначение, источники и память

У агента неизменяемое назначение `inbox` или `crm`, собственные profile/settings.
Inbox-агентов может быть несколько, CRM-агент один на Business. Переименование
не меняет identity/purpose. Отсутствующее legacy-purpose трактуется как Inbox.
CRM-агент не обслуживает клиентский канал. Его развитие сейчас на паузе;
существующие UI/API/память/аналитика сохраняются.

Новый агент не наследует знания, credentials или профиль другого. Собственные
BusinessKnowledgeItem имеют immutable bot ownership; shared library подключается
к каждому агенту явно. Подключать private knowledge другого агента нельзя.
Только активные разрешённые same-business материалы достигают prompt; запрос
без агента не получает shared library автоматически. Изменение/отзыв источников,
прав или настроек инвалидирует устаревшее подготовленное/queued действие/ответ.

Клиентский prompt содержит текущий диалог, публичные услуги/цены/доступность и
явно customer-visible знания. Private поля связанных CRM Client/Lead исключены.
`customer_visible` default false; общие/CRM-знания не публикуются автоматически.
Старые Inbox-owned материалы сохранили прежнюю аудиторию при миграции.
Shared connection требует `customer_visible` или явного `allow_customer_use`.
Сам флаг не проверяет все персональные данные — содержание проверяет владелец.

Память ограничена выбранным разговором/разрешёнными источниками, не является
полной безошибочной памятью всех записей. Staff Work/Analytics conversations
owner-private с дополнительными role/Business/source checks; источник не
становится общедоступным из-за сохранённого summary. Reset/retry/cancel не
обходят права и не оживляют отозванные команды. Актуальные слот/состояние/версия
проверяются перед действием, воспоминание модели не доказательство доступности.

## Матрица действий

| Сценарий | Разрешение и граница |
| --- | --- |
| Ответ клиенту | Разрешённые знания, готовые агент/канал; автоматическая отправка только при включённой политике и пройденных stop/review checks |
| Новый клиент | Связать/создать в разрешённом intake; существующие поля, включая пустые, не переписывать без staff confirmation |
| Новые Lead/Task/открытая Deal | Default `staff_confirmation`; controlled automatic creation только при явно включённых capability/политике, выраженном интересе или конкретном follow-up |
| Новая Appointment | Те же права/политика, явный выбор услуги, специалиста и точного предложенного свободного слота, повторная серверная проверка и replay protection |
| Existing record update, перенос/отмена, archive/delete | Подтверждение уполномоченным сотрудником и действующий доменный путь; не считать наличие инструмента универсальным CRUD |
| Staff CRM command | Точный preview → актуальный approval → повторная проверка underlying permission, record version, срока и agent identity → однократное исполнение |
| Деньги, роли, завершение сделки | Нет автономных финансовых/административных/terminal действий; нельзя превращать ответ/рекомендацию в разрешение |
| Handoff | Обязательные причины безопасности/отсутствия данных/человеческого review нельзя отключить режимом или высоким confidence |

Новый pipeline по умолчанию выключен; `staff_confirmation` и auto-reply не
включаются от одного выбора инструмента. Booking не меняет существующий lead
status автоматически. Не создавать все сущности на любое сообщение. Фраза
«записал» допускается только при подтверждённом факте сохранения. Повтор команды
использует исходный результат, не второй визит/сделку.

Для approval-gated tool новый ApprovalRequest всегда pending; создание запроса
не означает approved. Нужны approval точного tool call/command, текущие права,
время и версия. Mismatch/expiry/revocation останавливают исполнение с безопасным
audit. Capabilities не расширяют права actor. Ни произвольный ORM/SQL/shell,
ни filesystem/environment tool клиентской модели не предоставлены.

## Customer safety

Admission выполняется до платной классификации. Явные запросы секретов/обхода
инструкций/существующих личных записей передаются человеку без раскрытия.
Имя, телефон и «это моя запись» не доказывают личность; нельзя даже подтверждать
существование личной записи через этот сценарий. Неопределённая классификация
закрывает автономный путь. Поздравления/приветствия/благодарности не off-topic.

| Настройка | Default | Границы |
| --- | --- | --- |
| Первый безопасный off-topic ответ | Один короткий ответ разрешён | Можно отключить |
| Off-topic handoff | Третий вопрос; на втором фиксированное возвращение к бизнесу | 1–3 |
| Provider attempts / conversation / rolling 24h | 30 | 1–30 |
| Messages / minute | 12 | 3–30 |
| Message length | 4000 | 256–8000 |
| Repeated long messages / minute до handoff | 3 | 2–10 |

Второй одинаковый длинный текст пропускается без платного вызова; короткое
подтверждение слота не считается таким повтором. Счётчики хранят hashes/codes/
timestamps, не текст. Попытка модели резервируется до I/O; classification/reply
могут расходовать разные попытки, ошибки/неопределённые результаты остаются в
расходе. Параллельные запросы не превышают потолок. Новый диалог имеет свой
бюджет: общего нового business cap не утверждено.

Лимит останавливает AI, не сохранение входящих и ручную CRM. Resume требует
`conversations:update` + `ai_assistant:suggest`, открытого диалога и готовности
агента/канала. Сбрасывает поведенческие счётчики, но не provider usage; reset
памяти тоже не сбрасывает расход. При исчерпании дождаться истечения reservation.
UI показывает причину, расход и время следующего допустимого вызова, включая
снижение лимита. Pause/resume не оживляет старый ответ в очереди.

## Жизненный цикл, preview и сбои

Pause/draft/нет knowledge/profile останавливают автономный AI, а не transport
явно активного аутентифицированного канала и ручной ответ. Channel disable —
отдельное действие. Closed/archive/handoff stop states не разрешают pipeline;
спорная политика reopening фиксируется отдельно, не из старого draft.
После provider work и до outbox delivery eligibility проверяется снова.
Уже отправленный провайдеру запрос нельзя обещать отозвать задним числом.

Удаление агента — подтверждённая необратимая retirement с `ai_automation.delete`,
не reversible pause. History/audit/logs/созданные CRM-объекты сохраняются;
pending jobs/commands/approvals/auto-outgoing и относящиеся к его диалогам active
automation runs останавливаются. Другие агенты/общие правила продолжают работу.
Нет restore/reactivate path; одноимённый новый агент не наследует знания.

Preview в настройках использует сохранённый профиль и permissions, проверяет
одиночный запрос и показывает очевидную блокировку без вызова модели. Он не
создаёт CRM/Inbox сообщения, не отправляет клиентам и не уведомляет администратора.
Не воспроизводит накопительный Inbox ledger. Обычные provider calls preview
учитываются и могут сохранять AI-журнал; успешный preview не доказывает live-канал.

No-data, forbidden, unready provider и provider failure показываются честно.
Нельзя подменять ошибку уверенной локальной рекомендацией или скрытым mock.
Детерминированные подсказки не называют AI-выводом. Источники/ID/citations
валидируются и принадлежат разрешённому контексту; финансовые выводы идут по
[финансовому контракту](crm.md#деньги-и-аналитика), не по произвольным BusinessEvent.
Исторический аналитик использует текущие статусы записей периода, не реконструкцию
статусов на конец периода. История запросов до десяти лет не означает полную
семантическую достоверность ответов.

Распознаваемые credentials фильтруются до публикации, model input, output и
логирования. Это дополнительный фильтр, не универсальный DLP/prompt-injection
щит. Logs/audit не содержат сырых секретов/provider payload; provider cost
не равен начислению клиенту. Точные model/runtime options не дублировать
устаревающей таблицей; использовать runtime policy и сохранённый агент.
