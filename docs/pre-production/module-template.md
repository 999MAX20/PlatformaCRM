# Шаблон технического паспорта модуля

Скопировать структуру в документ конкретного модуля; этот шаблон не является
описанием реализованной функции. Заменить подсказки подтверждёнными фактами.

## Идентификация и статус

- Название и пользовательский результат.
- Дата среза, SHA реализации, ссылка на принятый контракт.
- Реализовано / проверено (какая среда) / опубликовано / развёрнуто / допущено.
- Входит ли в текущий пилот; пауза разработки отдельно от отключения runtime.

## Поведение и доступные действия

Основные reachable-сценарии, настройки и defaults, входы/выходы, используемые
сущности и инструменты. Для каждого изменения данных — условия, права,
подтверждения, жизненный цикл и наблюдаемый результат.

## Данные, права и защита

Источники, Business/роль, приватные поля, доступ к файлам, ограничения AI,
audit/activity/уведомления, исключённые действия. Не описывать отсутствие
доказательства как гарантированную безопасность.

## Ошибки и восстановление

Пустые данные, отказ доступа, недоступность зависимости, повторы/идемпотентность,
параллельные запросы, ручная альтернатива, rollback/восстановление.

## Техническая карта и среда

Ссылки на ключевые services/selectors/API/UI, зависимости и конфигурационные
имена без секретов, миграции и границы их применения. Версия провайдера/модели
указывается только если подтверждена для данного среза.

## Проверки и ограничения

Ссылки на отчёты и CI, дата/версия/среда, mock против live, пропущенные проверки
и причина. Не дублировать меняющиеся счётчики тестов из отчётов. Перечислить
недоказанные условия допуска; рекомендации не превращать в утверждённые задачи.

## Журнал изменений

Дата — наблюдаемое изменение — версия — доказательство/решение владельца.
