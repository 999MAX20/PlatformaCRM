## Прямой Scribe v3 — подготовка 17.11.2026

По разрешению владельца подготовлен отдельный ElevenLabs STT adapter с фиксированным
`model_id=scribe_v3`. **Не активирован для клиентских данных**.18.11 по новому разрешению прошли56
изолированных тестов и3 live synthetic RU-запроса (14.24с,8 кредитов из5000).
Исключение без ZRM действует только в отдельном тестовом harness с фиксированными
вымышленными фразами, не через рабочий API. Широкая точность RU/KK/mixed не доказана.
`VOICE_TRANSCRIPTION_PROVIDER` выбирает `openrouter` (текущий default) или `elevenlabs`.
OpenRouter-модель `VOICE_TRANSCRIPTION_MODEL` не управляет прямым адаптером.
Он требует `ELEVENLABS_API_KEY`, `ELEVENLABS_SCRIBE_ENABLED=True` и
`ELEVENLABS_SCRIBE_PRIVACY_CONFIRMED=True`; оба флага по умолчанию False, ключ пуст.
Последний флаг фиксирует предварительное подтверждение условий аккаунта оператором,
не является проверкой провайдера и не заменяет соглашение/проверку приватности.

Запрос идёт только на фиксированный HTTPS endpoint ElevenLabs с `enable_logging=false`.
В документации STT Zero Retention доступен Enterprise-клиентам. До активации нужны
подтверждённые права аккаунта на STT ZRM и условия запрета обучения на переданных
данных. При отсутствии подтверждения приложение отказывает до отправки аудио.
Нет ослабления приватности, автоматического повтора, fallback на OpenRouter/v2 или
перехода по HTTP redirect. Ключ остаётся на сервере, звук — только в памяти.

Синхронный multipart содержит WAV, `numbers_format=words`, отключённые события звука,
диаризацию, timestamps и webhook. RU подсказывает дополнительный KK и наоборот;
auto оставляет выбор языка модели. С18.11 начальный профиль соответствует RU/KK
языку интерфейса, сохранённый выбор (включая auto) имеет приоритет. При явном
включении контекста карточки сервер может добавить имя доступного клиента и части
его имени: максимум10 уникальных keyterms, каждый до50 символов/5 слов, только буквы,
пробелы, дефис и апостроф. Карточки задачи/записи дают только связанного клиента
после отдельной проверки его доступа; архивные данные исключены. Каталог бизнеса,
контакты и заметки в словарь не входят. Нет transcript editing
или исправления по большинству. Используется исходное поле `text`; прежние проверки
аудио/ответа, разбор телефона, права/Business и подтверждения CRM сохраняются.
`ready` проверяет конфигурацию выбранного адаптера, не баланс/доступность/точность.
API принимает необязательный multipart `current_entity` как JSON `{entity,id}`;
сырой словарь от браузера не принимается. Доступ перепроверяется после STT.
Словарь действует только для прямого ElevenLabs после прежней проверки приватности,
не отправляется OpenRouter и не сохраняется в AI-журнале. Рабочая активация выключена.
[Подготовка, ограничения и последующие проверки](../testing/evidence/voice-scribe-v3-20261117.md).

## Защита от ошибок распознавания, 18.11.2026

Все голосовые создания посещений, переносы и отмены требуют явного подтверждения
точной команды, включая существующего клиента. Предпросмотр показывает имя/время;
перенос показывает исходное и новое время. Прямой режим не обходит этот запрет.
Прежний просмотр новых клиентов/задач сохраняется. При смене доступа к клиенту
предпросмотр скрывается через существующую redaction. Неподдерживаемые действия
не расширены. Создание заметок и обычные чтения сохраняют прежний режим.

Резервный обработчик записи отвергает обнаруженные казахские отрицания и команды
внутри задачи, распознаёт форму «сағат … жаз». Контракты router/planner учитывают
«Әсел емес, Әсем» и исправление времени; это инструкция модели, не доказательство
качества live NLU. Буквальный разбор телефона поддерживает запятую после «плюс»;
известные искажённые метки требуют уточнения. Цифры не дополняются и не исправляются
догадкой, `numbers_format=words` сохранён. Синтетические ошибки самого STT и приёмка
живой речи остаются открытыми. [Проверки](../testing/evidence/voice-scribe-v3-20261117.md#improvements-20261118).

## Ошибки голосового ввода и диагностика — 12.11.2026

Ошибка распознавания отделена от ошибки последующего действия CRM. Панель RU/KK/EN
различает недостаточный баланс сервиса, таймаут, временную недоступность, лимит,
ошибку настройки, непригодный ответ, отсутствие речи и некорректную аудиозапись.
При временном сбое запись остаётся только в памяти: повтор выполняет пользователь,
с учётом Retry-After. Постоянный отказ не предлагает повтор той же записи;
можно удалить запись, записать заново или перейти к тексту. Автоповтора нет.
API сохраняет безопасный ответ code/retryable: HTTP402 → speech_payment_required,
408/504/socket timeout → speech_timeout; невалидный JSON → invalid_response.
Права, tenant scope, подтверждения действий и существующий timeout не изменены.
[Проверки без платных вызовов](../testing/evidence/voice-errors-20261112.md).

## Казахская и смешанная диктовка — решение11.11.2026

Распознавание может менять написание нового имени, повторяющиеся цифры или
название задачи. Модель не восстанавливает оригинал достоверно; утверждения о
безошибочном STT нет. Новые клиенты/задачи требуют просмотра по решению ниже.
Точное преобразование отдельных RU/KK/EN цифр поддерживает варианты метки
«телефон номер/номері/нөмірі». Неразобранная словесная диктовка телефона требует
уточнения до планирования полей и до записи, вместо угадывания цифр.
Русифицированное написание существующего клиента (например, і/и, ұ/у) служит
только основанием для уточнения среди доступных клиентов, не автоматического
выбора или переписывания имени. При исполнении такая неоднозначность проверяется
повторно. Права и tenant scope сохраняются. [Проверки и границы](../testing/evidence/voice-kazakh-20261111.md).

## Надёжность формата плана — 11.11.2026

Самостоятельный голосовой runtime выбирает фактическую модель до определения
JSON capability. Поддерживаемый default/tier профиль получает json_object на
маршрутизации и планировании полей, как явно заданная модель. Воспроизведённый
сбой возникал из-за отсутствия этого параметра и синтаксически неверного JSON
при точной расшифровке имени/телефона. Строгая проверка, no-partial-write и replay
сохраняются; неверный ответ не исправляется догадкой и не даёт нового платного
повтора. [Воспроизведение и повторные проверки](../testing/evidence/voice-planner-20261111.md).

## Выбор клиента при конфликте телефона — 11.11.2026

Совпадение имени не разрешает игнорировать другой указанный телефон. Если телефон
не совпал (включая отсутствие телефона у найденного клиента), помощник объясняет
конфликт RU/KK/EN и просит явно выбрать клиента или уточнить имя/телефон. До ответа
посещение и новый клиент не создаются. Явный выбор ID из уточнения сохраняет
исходные детали посещения и не изменяет телефон выбранного клиента.
Сопоставление использует общую нормализацию телефонов, включая 8/+7. Name/phone
параметры повторно проверяются при исполнении; нестрочный телефон отклоняется.
Права, атомарность, аудит и replay сохранены. [Проверки и ограничения](../testing/evidence/voice-identity-20261111.md).

## Подтверждение результата голосовой записи — 06.11.2026

Явная команда «запиши нового клиента … на …» не может завершиться только
созданием клиента. Если router вернул этот неполный шаг, сервер направляет
распознанную команду в существующий атомарный `crm_schedule`; старый неполный
план отклоняется при проверке исполнения. Команды задач/заметок и отрицания
не дают отдельного разрешения на запись. Распознаваемые явные формы RU/KK/EN
покрыты regression; это не сертификация всех произвольных формулировок.

Перед ответом об успехе `crm_schedule` сверяются число ожидаемых посещений,
уникальные ID результата и наличие соответствующих Appointment в том же Business.
Неполный/несуществующий результат приводит к `action_failed` и откату транзакции.
Ответ содержит число созданных записей; самостоятельное создание клиента
сообщает только «Клиент создан». Ответы RU/KK/EN следуют языку сотрудника.
Права, точная авторизация, доменные проверки, аудит и replay сохраняются.
[Причина, проверки и границы](../testing/evidence/single-location-20261106.md#voice-reliability-20261106).

## Филиал и уточнения записи — решение06.11.2026

Единственная допустимая точка выбирается автоматически. При нескольких точках
голос принимает current_branch из явного фильтра календаря/записей; сервер
проверяет Business, активность и доступ, связывает контекст с idempotency hash.
Явно названный в команде филиал имеет приоритет над контекстом страницы.
Без выбранного филиала единственная подходящая связка услуги/специалиста
разрешается автоматически; при нескольких уточняется филиал с сохранением
клиента, услуги, специалиста, даты и времени. В результате показывается филиал.
Нет действующей/доступной точки, нет услуги/назначения специалиста, занятое
время и прошедшая/невалидная дата имеют отдельные сообщения RU/KK/EN.
Прошедшая дата не переносится самостоятельно на следующий год.
[Проверки и границы](../testing/evidence/single-location-20261106.md).

## Связанные команды и история — решение06.11.2026

Сотрудник может одной отправкой найти или создать клиента и записать его на услугу,
либо создать план с несколькими датированными посещениями. Для нового клиента
достаточно имени; телефон необязателен. Поиск охватывает доступных клиентов Business,
а не только недавнюю выборку. Совпадения с неоднозначным именем требуют уточнения.
Нужны дата, время, услуга и специалист; единственный допустимый вариант можно
подставить, несколько вариантов без выбора — нельзя. Явное «любой свободный»
разрешает выбрать доступного специалиста. Ответ на уточнение дополняет исходный
запрос. Часовой пояс Business применяет сервер; модель не назначает отсутствующее время.

18.11: короткое исправление неподтверждённой записи или плана передаётся как
изменение отдельных полей сохранённого черновика. Остальные значения сохраняются;
для плана указывается номер изменяемого посещения. «Другой специалист» без имени
требует выбора, даже если в каталоге остался один вариант. При продолжении диалога
помощник задаёт один вопрос за раз. Исправление имени/телефона сбрасывает прежний
выбор ID клиента, если новый ID не указан явно и не проверен по доступным данным.
Отменённый, завершённый или исключённый из доступной памяти черновик не используется
как основание короткого исправления. Старое подтверждение отзывается; исправленное
предложение снова проверяет условия записи и требует просмотра/подтверждения.
Это поведение подготовки записи; распознавание живой речи и правильность выбора
полей моделью требуют отдельной проверки. [Проверки](../testing/evidence/voice-scribe-v3-20261117.md#short-corrections-20261118).

По результатам synthetic-пилота18.11 основной голосовой путь теперь останавливает
подготовку записи/клиента при распознанных явных отрицаниях записи на RU/KK/EN.
Та же защита действует при подтверждении сохранённого плана. Это ограниченный
лексический контроль, а не гарантия понимания любого отрицания; неоднозначные
составные команды требуют уточнения. Задачи с процитированным отрицанием и
исправление времени не получают запрет только из-за слова «не»/«емес».

Планировщик записи запрашивает строгую JSON-схему `voice_schedule` у моделей с
поддержкой JSON: оболочка `schedule`, полный черновик либо ограниченный patch.
В patch null означает неизменённое поле; имя/телефон относятся к клиенту, не к
посещению. Серверная проверка структуры, доступных ID и полей остаётся обязательной.
Невалидный ответ отвергается без автоматического повторного платного запроса.

Если короткий ответ не изменил черновик или распознанное исправление имени/телефона
оставило прежнее либо пустое значение, действие не предлагается к подтверждению.
Помощник просит уточнение, сохраняя прежние данные; для телефона просит полный номер.
Неразрешённое исправление имени/телефона сохраняется в доступной памяти этого
черновика и не снимается изменением другого поля. Явная отдельная новая запись
может начать полный черновик. Успешное исправление снова требует просмотра.

19.11: явные обозначения фамилии на RU/KK/EN также относятся к исправлению имени.
Если модель оставила прежнее имя, изменение времени или телефона не обходит уточнение полного
имени. До уточнения сохраняется прежний черновик целиком; после ответа требуется
новое подтверждение. [Локальная проверка и повторная live-матрица](../testing/evidence/voice-scribe-v3-20261117.md#pilot-candidate-follow-up-20261119).

Повторённые неизменённые время, исходная фраза времени и часовой пояс в patch не
требуют повторного произнесения времени при исправлении другого поля. Новое время
или изменение часового пояса по-прежнему требуют подтверждающей фразы последнего
ответа. Очистка неизвестного времени для уточнения сохраняется.

При первичном запросе записи на казахском точное совпадение извлечённого имени с
входной фразой и окончанием «ны/ні/ды/ді/ты/ті» служит ограниченным сигналом
неоднозначности, а не доказательством падежа. Если клиент не выбран по доступному
ID, помощник просит полное имя, сохраняя остальные поля. Окончание не отрезается;
явный ответ с такой же фамилией принимается без переписывания и снова требует
просмотра. Это не исправление ASR и не гарантия распознавания всех неоднозначных
имён. Пропуск фамилии и формы вне этого сигнала остаются отдельными ограничениями.

Потеря фамилии при первоначальном извлечении, ошибки ASR и устойчивость реальной
модели остаются открыты. Локальные регрессии не заменяют повторный live-пилот.
[Пилот](../testing/evidence/voice-scribe-v3-20261117.md#live-dialogue-pilot-20261118),
[исправления и проверки](../testing/evidence/voice-scribe-v3-20261117.md#pilot-fixes-20261118).

Связанная операция `crm_schedule` проходит существующие права, точную авторизацию,
идемпотентность и доменные сервисы клиента/записи/плана. Клиент, план и все записи
создаются одной транзакцией: конфликт любого посещения откатывает весь набор.
Цена, длительность, доступность и права перепроверяются перед исполнением.
Остальные AI-пути и правила критичных операций не расширены; новых моделей,
миграций, настроек среды и прав нет. Существующие события/уведомления доменных
сервисов сохраняются; отдельной рассылки голосовой истории нет.

Результат показывает найденного/созданного клиента, каждую запись с датой/годом,
услугой и специалистом, ссылку на план. Из панели доступна отдельная страница
`/app/voice/history`: только собственные голосовые диалоги текущего Business,
запросы/статусы/результаты и загрузка следующих страниц. Чужие и утратившие доступ
данные скрыты; исторические карточки не запускают повторные действия.
Во время записи один крестик закрывает панель, отдельные подписанные кнопки
отбрасывают запись и отправляют её; звуковая линия занимает всю строку.
Колокольчик и микрофон хедера имеют одинаковый размер и толщину штриха.

Код и локальные проверки согласованного scope завершены на66101d50 + WIP.
[Evidence](../testing/evidence/voice-workflows-20261106.md) содержит изолированные
тесты, PostgreSQL concurrency и семь сценариев реальной модели с синтетическими
данными. Human RU/KK/mixed/noise, полный D01 и production worker/recovery остаются
отдельной приёмкой; публикация заблокирована существующим Git lock/чужой историей.

## Прямая отправка и проверка новых объектов — решения05.11 и11.11.2026

Новые клиенты и задачи после голосовой отправки требуют просмотра распознанных
полей и явного подтверждения — решение владельца11.11 после проверки KK/mixed.
Для клиента показываются имя и телефон; для задачи — название и остальные поля.
Если новый клиент создаётся вместе с посещением/планом, всё остаётся одной
операцией: до подтверждения не создаются ни клиент, ни посещения. Запрос можно
исправить текстом; новое предложение заменяет старое. Отмена не создаёт данные.
С18.11 любое создание посещения, перенос и отмена также требуют просмотра.
Для остальных разрешённых команд нажатие «Отправить» сохраняет прямое выполнение.
Уточнение требуется для отсутствующих или неоднозначных данных. Это явная отправка
сотрудника, не фоновая автономия. Права, tenant, версии, доменные ограничения,
аудит и идемпотентность сохраняются. [Реализация и проверки](../testing/evidence/voice-direct-20261105.md).
API turns принимает `execution=direct` только для приватного voice/work диалога;
значение по умолчанию `review` сохраняет прежний протокол остальных callers.
Точная подготовка и выполнение прямого шага фиксируются одной транзакцией.
Для прямого шага ApprovalRequest связывает actor/параметры с
`authorization=voice_direct_submission`; просмотр новых клиентов/задач и создания,
переноса или отмены посещений использует
`authorization=review`, точную версию и fingerprint предложения. Внутренний direct
путь не может обойти эту проверку. Обязательны AI_PIPELINE
APPROVE/EXECUTE и права доменной операции. Потерянный HTTP-ответ повторяется с тем
же ключом; отмена/отзыв доступа до исполнения блокируют запись.

## Язык и приветствия — уточнение05.11.2026

Короткое приветствие не является запросом фактов CRM. Greeting/chat в голосовом
диалоге получают естественный ответ GPT-4o mini без инструментов и CRM-источников.
Общие вопросы разрешены; модель должна честно сообщать об отсутствии актуальных
внешних данных. История ограничена шестью доступными разговорными ходами того же
диалога и эпохи. Обычные агентские приветствия этим изменением не затронуты.
Приветствие перед командой не отменяет её обработку и серверную авторизацию.
Язык ответов голоса берётся из личного языка сотрудника RU/KK/EN, без AI-агента.
Язык распознавания auto/RU/KK независим: исходную речь требуется сохранять, не переводить.
Capture загружает обработчик до открытия микрофона, Stop ожидает все PCM-чанки.
Срез VOICE-REBUILD05.11: используются native sample rate и буферы1024samples,
эхо-/шумоподавление и AGC запрашиваются выключенными. Запись показывается после
первого PCM. Разрыв последовательности/входа, mute/ended, processor error,
приостановка контекста и отсутствие чанков приводят к явному отказу без отправки
обрезка. Обычная тишина не останавливает запись. Подавление звука оборудованием
или ОС и качество человеческой речи этим не сертифицированы.
Обычная формулировка «создай задачу позвонить поставщику» содержит название;
отдельное слово «название», цель, срок или исполнитель не требуются. Ответ на
уточнение дополняет незавершённую команду. Планировщик получает исходную реплику
вместе с выбранным шагом; язык ответа не должен переводить значения полей.
Прямая отправка использует STT-текст с точным преобразованием явно продиктованных
по одной цифр телефона (описано ниже), без дополнительного вызова модели
для пунктуации (`format_text=false`). Старые API callers по умолчанию сохраняют
форматирование с проверкой совпадения всех слов/чисел и их порядка.
Это не гарантирует точность самого STT. [Проверка диктовки и диалога](../testing/evidence/voice-natural-20261105.md).
Default распознавания остаётся Scribe v2. Кандидат Gemini 4 Carbon улучшил часть
казахских и смешанных записей, но строгая повторная проверка выявила остаточные
ошибки и новый пропуск повторяющейся цифры. Кандидат не принят как новый default;
прежние проверки Whisper/Scribe не доказывают качество этого кандидата.
[Сравнение, повторная проверка и незакрытые случаи](../testing/evidence/voice-accuracy-20261111.md).
Первоначальный live-срез проверял Whisper Large V3. Отдельная проверка Turbo05.11
прошла на синтетической русской записи через API с ZDR/no-data-collection,
реальной текстовой моделью и подтверждённой Task/replay. Семь команд через изолированный worker с реальной моделью прошли; production broker/recovery не проверены. [Новый срез](../testing/evidence/voice-hardening-20261105.md).
Локальные тесты языка ответа и приветствий
не доказывают качество распознавания реальной речи, смешанных языков или шума.
Проверки и граница: [срез языка](../testing/evidence/voice-language-20261105.md).

## Решение владельца 05.11.2026: самостоятельная функция интерфейса

Голосовое управление не требует создания, активации или настройки AI-агента.
Клиентский агент Inbox, агент управления/аналитики и голосовой интерфейс —
три самостоятельных механизма. Голос переиспользует безопасные инструменты CRM,
но не профиль, память, знания или employee workflow пользовательского агента.
Приватный голосовой диалог принадлежит сотруднику и Business, без ссылки на Bot.
Права сотрудника и ограничения действий сохраняются; новая явная отправка
обычной команды заменяет повторный просмотр, кроме новых клиентов/задач и создания,
переноса или отмены посещений по решениям11.11 и18.11 выше.
Независимость реализована и проверена локально:92 backend,6 browser,4 Node,
build/types/i18n, system/drift и чистый migration forward/reverse PASS.
[Новый срез и ограничения](../testing/evidence/voice-interface-20261105.md).
Рабочая миграция0009 применена05.11 после разрешения владельца и резервной копии.
Реальный OpenRouter STT→LLM→подтверждение→Task проверен через API и браузер
на синтетической русской записи. [Live-срез](../testing/evidence/voice-live-20261105.md).
Качество KK/mixed/шум и production rollout остаются отдельной приёмкой.

# CRM-D01 — голосовой помощник сотрудника

Владелец: [контракт AI](ai.md). Уточнения и реализация разрешены владельцем
04.11.2026. Провайдер выбран явно: OpenRouter. Статус05.11: голосовой сценарий
реализован и проверен локально; live-приёмка открыта.
Исходный scope — [D01](roadmap.md#crm-d01--помощник-сотрудника-аналитика-и-управление-crm-текстголос).
Этот документ не разрешает deployment или миграцию рабочей БД.

## Принятый пользовательский сценарий

Кнопка микрофона в глобальном хедере открывает компактную панель, сохраняя страницу.
На мобильном устройстве панель занимает доступный экран. Явное нажатие запускает
запись после разрешения браузера; постоянного прослушивания и слова активации нет.
Индикатор, уровень сигнала, таймер, остановка и отмена показывают реальное состояние.
Закрытие, уход со страницы, смена аккаунта/Business выключают микрофон и освобождают
audio tracks; запоздалые результаты другого контекста не показываются.

Запись → «Отправить» → распознавание на сервере → команда и проверки → просмотр
нового клиента/задачи либо создания/переноса/отмены записи и подтверждение → результат со ссылкой на CRM. Для остальных
команд этап просмотра не добавляется. При необходимости задаётся
вопрос; следующий ответ дополняет запрос. Лимит60сек только останавливает запись:
отправка остаётся явной. Текстовый ввод доступен при ошибке/недоступности микрофона,
а также через «Исправить запрос» для предложения или уточнения.
Последний приватный диалог восстанавливается по ID, сохранённому в sessionStorage
с ключом `voice-thread:v2:<user>:<business>`, без агента. Старые ключи
агентских диалогов не подхватываются голосовой панелью. Текст и история остаются на сервере;
ошибка доступа скрывает старые предложения и отключает подтверждение.
Отправка из голосовой панели авторизует конкретную обычную разрешённую команду.
Само произнесение или достижение лимита записи её не отправляет. Поиск/ответ
не вызывают изменения CRM. Предложения `execution=review`, новые клиенты/задачи,
создание/перенос/отмена посещений
сохраняют кнопочное подтверждение. Озвучивание ответов TTS исключено из первого
этапа; синтетические тестовые записи не являются продуктовым озвучиванием.

Состояния: idle, requesting_permission, recording, transcribing, transcript,
preparing, clarifying, awaiting_confirmation, executing, completed, failed.
В ходе recording доступны send/cancel; transcribing — cancel; после лимита —
send/cancel; при ошибке — явный повтор или текст. Исполнение недоступно при ошибке, отзыве доступа,
устаревшей версии или незавершённой подготовке. Повтор после ошибки — явный.
Закрытие панели не выдаётся за отмену уже отправленной серверной операции;
её результат восстанавливается из приватного диалога.

## Команды и контекст

Пилот: поиск клиента/записи, создание клиента/записи, перенос/отмена записи,
заметка и задача; фактические ответы с разрешёнными источниками. Одна бизнес-операция
за запрос; клиент+запись или план с посещениями — связанная операция `crm_schedule`
по решению06.11: новый клиент, план и все записи создаются одной транзакцией.
Конфликт любого посещения откатывает весь создаваемый набор; существующий клиент
сохраняется. Удаление/архивирование, массовые действия, неявка, деньги,
права и автономные изменения не входят в голосовое исполнение.
Нельзя молча превратить «не пришёл, удали» в отмену.
Слова «архив»/«не пришёл» внутри явно запрошенной задачи или заметки сами по себе
не запрещают текстовую операцию. Исключение требует соответствующего единственного
шага и явного маркера задачи/заметки до такого слова; другие формулировки могут
потребовать перефразирования. Оно не разрешает переход или архивирование.
Перенос только времени сохраняет текущего специалиста; указанная причина передаётся
доменному сервису. Текущие доступность специалиста, слот, права и версия проверяются
при исполнении. Отмена записи — transition cancel, не archive и не отмена диалога.
Планировщик получает только доступные инструменты и операцию выбранного шага;
сервер отвергает подмену типа операции. При создании новой сущности null-placeholder
для известного необязательного nonnullable поля пропускается; обязательные/неизвестные
поля и очистка существующих значений при update сохраняют строгую проверку.

Из читаемой карточки клиента и drawer записи можно открыть ту же голосовую панель
кнопкой микрофона в карточке. Она явно передаёт тип и ID независимо от URL;
фильтр клиента в списке записей не заменяет выбранную запись. Контекст отправляется
только после включения сотрудником флажка «Использовать открытую карточку».
Закрытие/смена карточки уничтожает её панель и запись, выбор контекста сбрасывается;
вход из общего хедера сохраняет определение карточки по URL. Панель внутри модального
окна входит в его область фокуса; Escape сначала закрывает панель.
Открытая карточка может передавать только тип и ID, явно показанные пользователю.
Сервер заново разрешает объект и его поля. Имена, телефоны, даты, часовой пояс,
услуга/специалист/слот требуют проверки; несколько совпадений — выбор/уточнение.
Приватные голосовые диалоги `kind=voice` принадлежат сотруднику и Business,
`agent=NULL`; они отделены от staff-диалогов агента и Inbox. Общие conversation
services, tools, approvals, domain services и аудит переиспользуются. Подтверждение связывается с параметрами/версией; исполнение
повторно проверяет доступ/слот, а replay возвращает сохранённый результат.

## Аудио и OpenRouter

Окно переделано под одну кнопку записи и живую прокручиваемую звуковую линию.
Расшифровка не выводится; ручной ввод доступен при ошибке/недоступности микрофона.
Показан последний ответ/уточнение, обработка или результат; постоянной ленты
карточек нет. Старые предложения review остаются явно подтверждаемыми.
История сервера остаётся приватной и используется для продолжения диалога.
[Текущие проверки и ограничения](../testing/evidence/voice-rebuild-20261105.md).

Неактивированный переход на прямой Scribe v3 описан выше. Действующий default
OpenRouter остаётся `elevenlabs/scribe-v2`, независимо от текстовой модели.
`VOICE_TRANSCRIPTION_MODEL` сохраняет явное переопределение; temperature=0.
Политика ZDR/no-data-collection остаётся обязательной; обхода при отказе нет.
Локальный кандидат adapter поддерживает явный `google/gemini-4-carbon`, но его
accuracy gate остаётся FAIL; итоговый default остаётся Scribe. Для этого
model ID adapter отправляет единственный аудиозапрос через
`/chat/completions`, без CRM-контекста и tools: статическая инструкция сохраняет
язык, казахское написание в смешанной речи и русское написание русской речи.
Телефон запрашивается словами по одной цифре. Явный язык ru/kk передаётся как
подсказка, не разрешение переводить речь. Текущий непринятый кандидат использует
статическую инструкцию на казахском, reasoning=medium, max_tokens=4096;
это не повторная текстовая коррекция STT. Обрезанный ответ, отказ, tool call,
невалидная структура, зарезервированные управляющие токены модели или текст
длиннее4000 символов не превращаются в команду. Метка телефона поддерживает
также разделители «—», «–» и «-». Экспериментальное голосование распознавателей
не входит в приложение: два распознавателя могут согласиться на лишней цифре.
После запятой или точки с запятой явная дата (день и название месяца RU/KK/EN
либо день.месяц.год) отделяет телефон от продолжения команды. Дата остаётся
нетронутой; произвольное цифровое продолжение не считается датой и не даёт
права обрезать номер. Эта граница не проверяет доступность или валидность записи.
Новые клиенты и задачи по-прежнему требуют просмотра и подтверждения: модель
не гарантирует оригинальное написание имени или точность каждого слова.
После STT сервер переводит только явно обозначенный телефон из7–15 отдельных
цифр RU/KK/EN в цифровую строку, сохраняя плюс и каждую цифру. Групповые, короткие
и неоднозначные числительные не исправляются; имена, даты и обычный текст не
подставляются из CRM. Это не восстановление цифр, потерянных самим STT.
[Сравнение моделей и проверка синтетических записей](../testing/evidence/voice-recognition-20261111.md).
Первоначальный `openai/gpt-4o-transcribe`05.11 реально вернул404 из-за отсутствия
ZDR-маршрута; модель заменена после успешной проверки с той же политикой приватности.
Явно выбранные специализированные STT-модели сохраняют `/audio/transcriptions`;
`openrouter/auto` не используется
для STT. Ключ выбранного STT-провайдера только на сервере; исходный звук не передаётся текстовым AI tools.
Запись до60 секунд, mono PCM16 WAV16kHz, файл до2MB. Сервер проверяет контейнер,
параметры, фактические frame bytes, длительность и пустой сигнал. Эти ограничения
принадлежат приложению, а не являются заявлением о лимитах провайдера.
Timeout60s, без автоматического платного повтора. Формат браузера преобразуется
в согласованный WAV перед передачей. При сбое доступен текстовый ввод.

Аудио хранится только в памяти во время записи/запроса, не в CRM, temp uploader,
истории диалога, аналитике или логах. Отправленный текст хранится как обычное
сообщение приватного сотруднического диалога; неотправленный — локальное состояние.
Провайдер получает ограничения `zdr: true`, `data_collection: deny`; если маршрут
не совместим, обработка должна отказать, а не ослабить политику. Настройки платформы
и фактическая совместимость маршрута требуют отдельной проверки перед live-приёмкой.
Отмена браузером прекращает ожидание и удаляет локальный звук; не обещает отмены
уже принятого провайдером запроса или его стоимости.

GET `/api/ai/speech/?business=ID` возвращает Business, readiness и
лимиты, без поля agent. `ready` означает наличие включённых флагов и конфигурации,
а не успешный health-check модели. При отказе STT показывается ошибка, введённый
текст сохраняется; повтор записи запускается вручную, автоматического платного
повтора нет. POST multipart `business`, `language=auto|ru|kk`, `audio`,
optional `format_text` (default true, панель передаёт false) возвращает только
текст/длительность. До и после распознавания проверяются текущие actor/Business,
AI_ASSISTANT SUGGEST. Создание голосового диалога использует `kind=voice`
без agent; передача агента или режима analytics отклоняется. Встроенный runtime
использует настройки сервиса и служебные инструкции приложения, а не профиль,
модель, знания или employee workflow пользовательского агента. HTTP ответ no-store.
Ошибки не раскрывают provider body, URL, token или содержимое аудио.

## Личные настройки

В Настройках: видимость кнопки в хедере (default on), язык (default auto, RU/KK),
микрофон текущего устройства (default system) и проверка уровня звука.
Настройки хранятся в текущем браузере отдельно для пользователя. Раздел доступен
по `/app/settings/voice` с AI_ASSISTANT SUGGEST без SETTINGS UPDATE; тот же блок
есть в общих Настройках. Ссылка из Аккаунт → Интерфейс остаётся доступной,
когда кнопка скрыта, поэтому её можно включить обратно без административных прав.
Скрытие кнопки не выключает серверные полномочия и не меняет настройки коллег.
Проверка микрофона не отправляет звук провайдеру. Нет выключателя подтверждений,
TTS, фонового прослушивания или provider keys в ежедневном интерфейсе сотрудника.

## Проверки и граница готовности

Каждый backend-срез проходит focused isolated tests до зависимого UI. Обязательно:
форматы/лимиты/тишина/timeout, отсутствие аудио в хранении/логах, role/tenant,
отзыв доступа, недопустимые команды, точное approval/stale/replay/rollback.
UI: desktop/mobile, RU/KK/EN, keyboard/focus/Escape, permission denied/no microphone,
cancel/re-record, отправка без промежуточного текста, fallback, уточнения/результат,
network/retry, business switch.
Завершение: affected/dependent AI suites, system/drift, build/types/i18n и reachable
browser flow. Synthetic provider доказывает обработку, но не качество распознавания.
