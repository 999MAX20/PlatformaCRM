# Вопросы владельцу по пилоту PlatformaCRM

Владелец разрешил последовательное выполнение всех семи этапов без ожидания
ответов ночью. Здесь фиксируются только решения, которые нельзя безопасно
придумать. Независимые локальные результаты зафиксированы в
[PRIMARY-SESSION](../testing/task-state/PRIMARY-SESSION.md); ответов пока нет.

| ID | Вопрос и рекомендуемый вариант | Что блокирует; независимая граница |
| --- | --- | --- |
| Q01 / BE-GAP-004 | Может ли platform_manager изменять support-note при активном grant и MFA? Рекомендация: до отдельного разрешения ограничить mutation platform_admin согласно строгой строке матрицы; потребуется согласовать противоречащий код/описание | Только окончательную policy и приёмку support-note. Merchant role/tenant проверки выполняются независимо; права самовольно не меняются |
| Q02 / BE-GAP-007 | Какая целевая среда пилота, кто оператор, какие RPO/RTO и куда хранить backup? Рекомендация: отдельная staging/pilot среда, раздельные secrets, проверяемое восстановление | Deployment и допуск реальных данных. Локальные синтетические проверки/runbook не требуют этого решения; ничего не покупается |
| Q03 / BE-GAP-011 | Сроки хранения/удаления файлов и резервных копий, допустимые форматы/размеры и требуемый антивирусный сервис? Рекомендация: утвердить сроки и карантинную политику до внешнего допуска | Применимую production lifecycle/антивирусную конфигурацию. Проверки имеющихся private-media/tenant/type guards выполняются независимо |
| Q04 / финальная приёмка | Какая клиника и какие сотрудники выполнят итоговые сценарии, какие реальные данные разрешены? Рекомендация: сначала синтетический проход администратором/руководителем, визуальная и ручная screen-reader проверка, затем отдельно разрешённые реальные данные | Пользовательскую приёмку, ручной FB-009/UX-4 и допуск клиники, не локальные UI/API тесты |
| Q05 / качество live AI | Какая модель/провайдер разрешены для проверки реальных ответов и какой лимит расходов? Рекомендация: после выбора среды прогнать утверждённые рабочие вопросы на синтетических данных | Только оценку качества live LLM. Детерминированные grounding/approval/permission/failure проверки выполняются без платных вызовов; mock не выдаётся за оценку реальной модели |

Внешние интеграции, мессенджеры, 1С/МойСклад, платёжный шлюз и billing в текущий
прогон не входят. Не нужны ответы о них для продолжения внутренней CRM/AI.
Новые вопросы добавляются с точным сценарием и ссылкой на evidence; старые
согласованные решения повторно не запрашиваются.
