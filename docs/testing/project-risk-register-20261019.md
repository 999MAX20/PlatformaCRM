## Как читать результат

- **Подтверждённый дефект:** конкретный сценарий и нарушение требования с evidence.
- **Риск:** источник опасения известен, но вредный результат ещё не доказан.
- **Архитектурный долг:** сопровождение/связанность; сам по себе не security finding.
- **Пробел доказательств/среды:** отсутствие достаточной проверки, не отсутствие кода.
- **Решение владельца:** правило нельзя выбрать технической догадкой.

Статусы: **Выполнено полностью / Выполнено частично / Не выполнено**.
Полное выполнение всегда ограничено названным scope. Deployment, реальный provider,
целевая инфраструктура и приёмка сотрудниками не следуют из локального PASS.
Карточка: ID → сценарий/последствие → тип/доказательство/версия → статус → сделано →
остаток (код / доказательства / среда / решение) → критерий закрытия → связанные IDs.
Обсуждения не создают новые требования без принятого решения; прежние оценки процентов
готовности не являются измерением безопасности, покрытия или текущей версии.

## 6. Повторный полный аудит — поручение и граница

Владелец разрешил свежий repository-wide аудит после консолидации. Обязательный фокус:

- SQL: raw/execute/extra/order/filter и динамические identifiers; источник входа,
  параметризация, allowlist, tenant scope; наличие ORM само по себе не доказательство.
- HTTP/API: auth/session/CSRF/CORS, IDOR, массовые изменения, webhooks/replay,
  rate/size limits, XSS/redirect/header handling; исходящие URL, SSRF/DNS/redirects,
  provider credentials и разрешённые адреса.
- Вложения к сущностям и клиентам, аватары: разрешённые типы/расширения и реальный
  формат, active HTML/SVG/scripts/polyglots, image decode/re-encode и resource budgets,
  AV/quarantine/fail-closed, filename/path traversal, архивы/распаковка, размер/квоты.
- Выдача файлов: tenant/record permission на upload/link/download/delete, storage
  вне executable web-root, приватность URL, Content-Type/Disposition/nosniff, origin,
  публичные avatar URLs, отзыв доступа, отсутствие исполнения на сервере/в браузере.
- Прочие границы: роли/platform/MFA, секреты, AI tool/approval/grounding, деньги,
  lifecycle/concurrency/idempotency/queues, зависимости и deployment configuration.

Файл не исполняется только из-за факта загрузки. Проверяется реальная цепочка:
кто загружает → что валидируется → где хранится → кто/как получает → каким
интерпретатором/браузером обрабатывается → какие полномочия доступны.
Не утверждать, что AV или запрет одного расширения закрывает все эти цепочки.

Исходники и конфигурация проверяются без атак на рабочий сервер, реальных внешних
отправок и изменения пользовательских файлов/БД. Результат должен содержать новые
подтверждённые findings, опровергнутые подозрения, проверенные защиты и честные пробелы.
Новый security finding получает отдельный ID только при отсутствии дубля AUD.
Runtime fixes выполняются последующими поручениями, а не автоматически в аудите.
