# Финансовый источник V1-M01/M02

Решение владельца 2026-10-02 заменяет исключение ручного журнала от 22.09:
бизнес явно выбирает ручной журнал CRM (`financial_source_mode=manual`) либо
один внешний источник (`external` + `financial_connector`). Источники не
выбираются автоматически и не суммируются. Без выбора внешнего коннектора —
`no_source`. [Правила V1](../product/V1_PRODUCT_RULES.md) и
[ручной журнал](../crm/client-payments.md) определяют продуктовую границу.

Ручной источник считает все доступные операции Payment выбранного периода в
часовом поясе бизнеса: поступления, возвраты и их разницу. Требуются BUSINESS
права analytics, payments и clients. Coverage — `recorded_manual_operations`,
не независимая гарантия полноты бухгалтерии; пустой журнал означает ноль
зарегистрированных операций. `last_recorded_at` показывает последнюю запись,
`last_successful_sync_at` остаётся null. Несовпадение валют делает итог недоступным.
Прибыль и задолженность не рассчитываются: расходы/начисления не входят в scope.

## Общий API

`owner-dashboard` и `reports/summary` возвращают объект `financial`:

| Поле | Контракт |
| --- | --- |
| `state` | unavailable, available или stale |
| `reason` | Причина отсутствия/предупреждения, либо null |
| `period.start/end` | Точные включённые даты запрошенного периода |
| `source` | id, name, provider разрешённого источника; иначе null |
| `last_successful_sync_at` | Реальное finished_at успешного запуска, создавшего снимок |
| `currency` | Валюта бизнеса; несовпадающий снимок отклоняется |
| `receipts/refunds/net_receipts` | Decimal-строки либо null; итог = поступления минус возвраты |

При unavailable суммы и время снимка равны null. Для внешнего источника ноль
допустим только для полного проверенного периода без операций. Dashboard запрашивает
сегодня в часовом поясе бизнеса, summary — существующий ограниченный период.
Интерфейс показывает период, источник и фактическое время успешного обновления.

Общий снимок требует существующего `analytics:view` со scope BUSINESS и
доступной capability. OWN/TEAM не раскрывают whole-business finance, включая
название источника и старые снимки. Новые разрешения/роли не вводятся.

## Проверка источника

Production `FINANCIAL_SOURCE_READERS` сейчас пуст. Ни один существующий импорт
или messaging adapter не доказал полноту учётного периода. Connected, finance
capability, payload verified=true, healthcheck и успешный generic import не
сертифицируют финансы. Live источник этот пакет не добавляет; положительные
состояния проверяются только изолированными fixtures.

Будущий adapter регистрируется через review кода. Reader читает локально
сохранённые FinancialSnapshot точного периода, без сетевого запроса в отчёте.
Конкретный adapter должен отдельно доказать полноту/сверку поступлений и возвратов,
сохранение предыдущих снимков при ошибке и связь с успешным sync run.
Persistence, внешние операции и правила сверки входят в задачу такого коннектора.
Тестовый reader нельзя регистрировать в production.

Общий слой проверяет Business/connector/run, даты, валюту, конечные
неотрицательные Decimal-суммы и согласованность количества операций. Sync run
должен быть успешным, не healthcheck, с завершением не в будущем. Несколько
источников не выбираются и не суммируются автоматически.

## Ошибки и актуальность

Ошибка/остановка коннектора сохраняет последний доступный проверенный снимок
точного периода со state=stale. Неполный снимок не заменяет старый. Сохраняются
суммы, источник и время успешного обновления. Без снимка — no-data; первая
незавершённая загрузка — initial_sync. Ошибка локального чтения reader —
source_unavailable, без выдуманных сумм или раскрытия текста исключения.

Произвольный TTL не вводится. Просроченное существующее next_sync_at даёт
sync_overdue; выполняющийся запуск — updating; новый успешный запуск, не
подтвердивший период, — snapshot_not_refreshed. last_sync_at не является датой
успешного обновления: существующий sync слой меняет его и при ошибках.
Старые суммы никогда не подписываются как данные на текущую минуту.

## Потребители

- Legacy revenue_estimate, revenue totals и ltv_estimate возвращают null.
  service_value_estimate, average_service_value_estimate и
  operational_values.completed_services_estimate сохраняют явную оценку услуг.
- CSV source/retention exports используют новые явные имена; это не экспорт
  поступлений. Суммы сделок подписаны как суммы сделок, не фактические поступления.
- AI BusinessEvent Analyst использует события только как операционные источники.
  Денежные поля исключены из event payload; prompt/source policy запрещает
  финансовые выводы из событий. Отдельный `/api/ai/analyst/history/` использует
  этот финансовый контракт, полные агрегаты периода и сравнение равных периодов;
  свободный AI-ответ строится по вычисленному отчёту с повторной проверкой источников.
- Ручной журнал сохраняет Payment/history/replay/links/permissions. SaaS billing,
  AI credits, уведомления и BusinessEvent write paths не меняются.

Gates, candidate и публикация — в [checkpoint](../testing/task-state/PRIMARY-SESSION.md).
Это контракт реализации, не заявление о подключённом учёте или приёмке клиникой.
