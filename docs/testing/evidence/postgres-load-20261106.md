# POSTGRES-LOAD-20261106 — локальная PostgreSQL и нагрузка

Поручение владельца: перенести локальную CRM с SQLite на PostgreSQL с сохранением
данных и резервной копией, измерить одновременных пользователей и запросы.
Канонический checkout: `C:/Users/user/Desktop/PlatformaCRM`, ветка
`codex/ui-testing-toolkit`; исходный HEAD `d6cf58294bdbdbeca58879e3a5d227cd2140ebae`
с существующими чужими изменениями. Production не затронут.

## Перенос и сохранность

Рабочая CRM использует PostgreSQL17.10 на `127.0.0.1:55432`, БД `platformacrm`,
роль `crm_app` без superuser. Отдельный кластер находится в
`output/local-postgres/data`; прежний PostgreSQL5432 не менялся.
В `.env` изменён только `DATABASE_URL`; секреты в этом отчёте не содержатся.
Исходная `db.sqlite3` сохранена, автоматический откат к ней не включён.

Перед переключением остановлены проверенные локальные API/import worker и задание
очистки токенов, сделана финальная SQLite-копия. Перенесены все152 таблицы,
10117 строк: проверены значения каждого поля с нормализацией SQL-типов, PK,
последовательности и внешние ключи. Парольные хеши, идентификаторы и ссылки на
файлы сохранены. `pg_dump` восстановлен в отдельную `crm_restore_check`;
повторная сверка всех полей с SQLite также PASS.

содержат рабочие данные и не включаются в Git или публичные архивы.
Откат требует остановки писателей и учёта всех новых записей PostgreSQL после
переключения: простая замена URL вернула бы старый срез и потеряла новые изменения.

Локальные API и worker перезапущены с PostgreSQL. Десять авторизованных HTTP200
запросов к филиалам сопоставлены с реальными PostgreSQL-сессиями/SQL.
Финальный read-only срез:16 бизнесов,25 клиентов,14 визитов,32 сделки,3 задачи;
API health и frontend HTTP200, восстановленная копия снова полностью совпала.
Windows-задания `PlatformaCRM-Local-PostgreSQL` при входе и
`PlatformaCRM-Local-ExpiredTokens` ежедневно12:00 завершились с кодом0.
`dev.ps1` проверяет/поднимает только закреплённый локальный PG-профиль.

После переключения другой задачей добавлены choices-only миграции
`bots.0014_historical_delivery_resolution` и
`integrations.0009_historical_delivery_resolution`. Они не применены к рабочей БД
в рамках этого переноса. Финальная проверка показывает эти две ожидающие миграции;
утверждение «текущий checkout не имеет backlog миграций» не делается.

## Методика нагрузки

Windows, Intel Core i3-1315U,6 ядер/8 потоков, около7.7GiB RAM; клиент нагрузки,
PostgreSQL, API и остальные приложения используют один компьютер. Это измерение
данной локальной среды, не предел проекта на выделенном production-сервере.

Тесты работают на отдельных `crm_bench_small`/`crm_bench_large`, восстановленных
из dump, с10 синтетическими бизнесами и320 отдельными авторизованными пользователями.
Обычные проверки ролей, tenant isolation, JWT/device sessions сохранены.
Отдельные Redis/API/Celery, `DEBUG=False`, Uvicorn, `DB_CONN_MAX_AGE=0`;
API workers указаны в таблице результатов. Внешние провайдеры/AI отключены.
После прогона собственные процессы и тестовая БД удаляются автоматически.

Смесь:20% список клиентов,10% поиск клиентов,10% визиты,20% список задач,
10% сделки,10% карточка клиента,10% dashboard,10% создание задачи.
Пользовательский профиль — последовательные запросы с паузой1с между ними;
inflight — запросы без паузы. Это виртуальные API-пользователи, не открытые вкладки.
Этапы по60с, warmup15с; SLO задан до измерений: ошибки<1%, p95≤1000мс.
После двух провальных ступеней повышение прекращается.180с проверка предусмотрена
только для найденной проходящей ступени. Количество созданных задач сверяется с201.

## Проверки и границы

- 16 focused unit tests (`python -m unittest scripts.tests.test_local_postgres
  scripts.tests.test_dev_local -q`) PASS: профиль, запреты чужой БД, типы/hash,
  локальный launcher; повторены при завершении.
- 141 изолированный PostgreSQL тест PASS: auth, token cleanup, tenant isolation,
  scheduling, working-hours/record/plan concurrency, initial-location migration,
  payments, import engine/concurrency. Точные labels и результаты находятся в
  `output/postgres-load-20261106/postgres-verification.log`.
- Чистые тестовые миграции, system check и drift PASS на срезе до двух поздних
  migrations. Финальный working backlog сохранён выше; старый PASS его не скрывает.
- Репетиция сначала выявила PK Django sessions и нормализацию inet; исправлено,
  финальная полная сверка и повторное восстановление PASS.
- Первый restart унаследовал SQLite env, затем возникли launcher lock/timeout
  при нехватке RAM. Последующий реальный API→PG proof PASS; ошибки сохранены.
- `output/postgres-load-20261106/final-verification.json` содержит финальные
  hashes/parity, counts, health и реальные pending migrations.

Каталоги результатов содержат endpoint percentiles/statuses, CPU/RAM, записи задач
и очереди. `subjects.json` содержит временные токены, не публикуется.
Не проверены нагрузка браузерного рендера, AI/STT, импорт больших файлов,
внешние провайдеры, отдельный сервер, длительная многосуточная работа.
Frontend build/full E2E не запускались: UI не менялся; это не release certification.
