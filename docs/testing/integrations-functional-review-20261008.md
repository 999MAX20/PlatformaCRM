## Главный вывод

Страница объединяет четыре разные задачи: импорт файла, настройку источника,
заявку на будущий сервис и контроль обмена. Интерфейс показывает их как одинаковые
«подключения». Поэтому часть статусов и действий не соответствует реальному
сценарию: импорт называется подключением, ожидающий настройки источник может
исчезнуть из фильтра внимания, а ошибка сохранения остаётся за модальным окном.

Локальный CSV-импорт клиента действительно прошёл от загрузки до подтверждения.
Внешняя синхронизация и готовность 1C/МойСклад этим аудитом не подтверждены.
Редизайн целесообразно строить вокруг конкретного следующего действия и точного
состояния, одновременно устраняя найденные функциональные расхождения.

## Состояния, безопасность и эксплуатация

- Loading страницы уже есть. При error нельзя подставлять счётчики из каталога
  вместо данных бизнеса. Partial failure capabilities/connectors/history нужно
  показывать раздельно, сохраняя только действительно безопасные действия.
- No business и no search results реализованы. Пустые подключения, отсутствие
  истории и отсутствие совпадений — разные сообщения и разные CTA.
- У импорта есть preview до confirm; backend проверяет create права целевой
  сущности, enabled resource, файл, повторное подтверждение и пишет audit.
  Confirm выполняется transaction.atomic. Это найденные механизмы, а не результат
  нового полного прогона rollback/concurrency/всех permission combinations.
- Generic config отклоняет секреты, сериализаторы очищают чувствительные поля;
  специально обходить защиту для работающей формы нельзя. Dedicated МойСклад
  использует защищённый credential flow. В референс нельзя вводить реальные токены.
- В коде существуют regression suites на импорт/дубликаты/ошибки/идемпотентность,
  credentials masking/encryption и tenant permissions. Их наличие не равнозначно
  свежему PASS; в этой задаче они прочитаны выборочно, не запускались целиком.
- Есть audit и нормализованные BusinessEvent. Редизайн не должен превращать факт
  сохранения настроек в доказательство синхронизации, продажи или revenue.
- По коду выполняется отдельный запрос sync runs на каждый найденный connector
  даже при закрытой настройке. Для пяти провайдеров это ограниченный fan-out;
  измеренного performance incident нет. При расширении списка стоит отдавать
  краткое последнее состояние вместе с connector, историю загружать по открытию.
- Реальные external sends, live sync, worker retries, provider credentials,
  production observability, deployments и отключение интеграций не проверялись.

## Предлагаемый редизайн

### Состав страницы

1. Общий app header «Подключения» и существующий плоский sidebar. Один заголовок,
   без маркетингового подзаголовка и плашки «Без технических токенов в CRM».
2. Фильтры «Все / Подключены / Требуют внимания» с данными выбранного бизнеса,
   отдельный поиск «Найти сервис», основной CTA «Импортировать файл».
3. «Импорт данных»: Excel/CSV и последний импорт при наличии данных. Не считать
   его постоянным подключением во вкладке Connected.
4. «Внешние сервисы»: короткие строки МойСклад/1C с настоящим статусом и одним
   понятным действием. Для первого — «Настроить», для отложенной 1C — сведения
   о доступности; активную заявку показывать только при подтверждённом workflow.
5. «Планируются»: Google Sheets/Email с нейтральным статусом, без disabled
   зелёных «Подключить» и без обещаний сроков.
6. Контекстная панель с данными выбранного сервиса. На узком экране один столбец,
   настройка занимает доступную ширину. В реализации переиспользовать shared
   Drawer/Modal и их focus management, закрытие Escape и возврат фокуса.

### Панели и действия

Настройка МойСклад: сохранён ли токен (никогда не его значение), выбор данных,
состояние окружения/доступности, понятная ошибка рядом с действием. «Проверить»
и «Загрузить» включаются только при выполненных prerequisites и разрешённом
provider rollout. Request, credentials, connection health и sync progress —
разные состояния; один зелёный badge их не заменяет.

Импорт: три шага «Файл → Проверка → Результат», данные и шаблон на первом;
число корректных строк, причины ошибок и дубликаты на втором; подтверждение с
количеством записей; результат с конкретным действием. История доступна отдельно
в том же сценарии, но не занимает четыре вложенные карточки до выбора файла.
Новые mapping/обработка дубликатов не входят автоматически в визуальный scope:
сначала использовать текущий backend contract.

Статус подключённого сервиса: последнее успешное обновление в согласованном
часовом поясе, текущая операция, результат, безопасная ошибка, разрешённый повтор.
Read-only роль видит детали без кнопок изменения. Неуспешный запрос истории
отображается как ошибка истории, а не «операций нет».

### Дизайн-система

Использовать существующие semantic tokens и компоненты, а не новую тему:
canvas `#F6F8F7`, surface `#FFFFFF`, subtle `#F0F4F2`, border `#D7E1DC`,
text `#17201E`, secondary `#4F5E58`, brand `#007A59`, brand-soft `#E4F3ED`.
Manrope с принятым fallback для KK; card radius 12px, controls 10px, modal 16px.
Отступы 8/12/16/24px, слабая тень только у необходимой поверхности.

Переиспользовать PageHeaderContext, Button, Input, Select, StatusBadge/Badge,
StateViews, Drawer/Modal. Зелёный обозначает действие/активность, а не каждую
плитку; предупреждения и ошибки используют существующие семантические токены.
Не создавать новые KPI, тарифные обещания, провайдеров или обучающие блоки.

Интерактивный референс показан в ответе задачи: каталог без подключений,
поиск/фильтры, панель МойСклад с локальной валидацией и демонстрационный
трёхшаговый импорт. Дополнительные состояния — ошибка загрузки и плотность
списка. Это ограниченный макет, не подключение к API; пример импорта не меняет
CRM. Новые короткие подписи в нём — предложение copy, не утверждённые i18n строки.

## Рекомендуемая следующая ограниченная задача

Если владелец выберет реализацию, единый результат — достоверная страница
подключений в текущей дизайн-системе: scoped данные, согласованные статусы,
видимые ошибки, корректные действия и новый layout. Сначала исправить P1 и
контракты состояния, затем UI. Не начинать внешние интеграции или CRM AI.

Приёмка: business scope и несколько connectors; attention и unavailable;
partial failure/retry; request state; секреты через разрешённый endpoint или
отсутствие неподдержанной формы; import preview/error/confirm; manage/view/denied;
desktop/mobile keyboard; RU/KK/EN; affected backend после coherent change,
targeted UI tests и одна финальная frontend сборка. Права, money, external
effects, уведомления и BusinessEvent не менять без предметной необходимости.
