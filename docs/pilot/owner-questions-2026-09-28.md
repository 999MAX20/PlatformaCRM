# Вопросы владельцу по пилоту PlatformaCRM

Владелец разрешил последовательное выполнение всех семи этапов без ожидания
ответов ночью. Здесь фиксируются только решения, которые нельзя безопасно
придумать; независимая реализация и проверки продолжаются. Ответов пока нет.

| ID | Вопрос и рекомендуемый вариант | Что блокирует; что продолжается |
| --- | --- | --- |
| Q01 / BE-GAP-004 | Может ли platform_manager изменять support-note при активном grant и MFA? Рекомендация: до отдельного разрешения ограничить mutation platform_admin согласно строгой строке матрицы; потребуется согласовать противоречащий код/описание | Только окончательную policy и приёмку support-note. Merchant role/tenant проверки продолжаются; права самовольно не меняются |
| Q02 / BE-GAP-007 | Какая целевая среда пилота, кто оператор, какие RPO/RTO и куда хранить backup? Рекомендация: отдельная staging/pilot среда, раздельные secrets, проверяемое восстановление | Deployment и допуск реальных данных. Локальные синтетические проверки/подготовка runbook продолжаются; ничего не покупается |
| Q03 / BE-GAP-011 | Сроки хранения/удаления файлов и резервных копий, допустимые форматы/размеры и требуемый антивирусный сервис? Рекомендация: утвердить сроки и карантинную политику до внешнего допуска | Применимую production lifecycle/антивирусную конфигурацию. Проверки имеющихся private-media/tenant/type guards продолжаются |
| Q04 / финальная приёмка | Какая клиника и какие сотрудники выполнят итоговые сценарии, какие реальные данные разрешены? Рекомендация: сначала синтетический проход администратором/руководителем, затем отдельно разрешённые реальные данные | Пользовательскую приёмку и допуск клиники, не локальные UI/API тесты |

Внешние интеграции, мессенджеры, 1С/МойСклад, платёжный шлюз и billing в текущий
прогон не входят. Не нужны ответы о них для продолжения внутренней CRM/AI.
Новые вопросы добавляются с точным сценарием и ссылкой на evidence; старые
согласованные решения повторно не запрашиваются.
