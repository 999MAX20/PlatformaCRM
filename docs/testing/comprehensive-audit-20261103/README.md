# Комплексный аудит PlatformaCRM — 03–04.11.2026

**Проверки и отчёты подготовлены. Полная готовность к production не подтверждается:
есть воспроизведённые дефекты и незакрытые обязательные требования.** Исправления
продукта не входили в аудит. Ограничение локального сохранения части активных

## Основные выводы

1. **Автоматическая запись расходится с ручной в трёх местах.** Без филиалов
   принимает изменённые цену/длительность после доставленного клиенту предложения:
   предложено100/30мин, создано200/30 либо100/60. Не сохраняет новые поля
   ответственного/исходного диалога и пропускает настроенное правило
   `appointment_created → создать задачу`. Проверены реальные доменные записи и
   эффекты в изолированной БД с положительными контролями. Денежных списаний и
   реальных сообщений не было. CRM-TERMS01, REQ03, CRM-EVENT01.
2. **Список клиентов слишком дорог на проверенном объёме.** На синтетическом N=1000
   объектов каждого типа SQLite даёт18.4s median; распределённый контроль17.26s
   за один запрос. PostgreSQL HTTP warmup —28.618s. Каждый из двух профилей
   по50 запросов дал40HTTP200 и10таймаутов Clients на10s deadline. Это риск рабочего
   сценария, не оценка мощности облака. Текущие очереди записей выполняют387–1737SQL,
   карточка клиента184SQL. PERF01–03.
3. **Аварийный экран сам падает:** Button требует отсутствующий I18nProvider;
   независимый контроль с провайдером проходит. **Compose не задаёт consumers для
   notifications, automations, reports_exports.** Это дефект поставляемой топологии,
   не утверждение о неизвестном работающем сервере. UI01, OPS-Q01.
4. **Полный денежный цикл планов и голосовой D01 отсутствуют.** Неденежные планы,
   записи, журнал оплат и текстовые AI-инструменты реализованы и имеют scoped
   доказательства. Они не заменяют версии пакетных цен, авансы/зачёты/остатки/возвраты
   плана и голосовой сценарий. Закрытия отдельных пакетов не отменены и не превращены
   в полную приёмку14 AC. REQ01–02.
5. **Подтверждены UI-дефекты:** поиск задач только по первой странице, ложное пустое
   состояние Clients при ошибке, семантика/клавиатура общего picker, локализация дат,
   приглашение и false-dirty сохранённого AI-профиля. Дизайн-система сохраняется;
   косметический редизайн не предложен как обязательное исправление.
6. **Исторический native нельзя считать готовым текущим приложением.** Actual-source
   пробы выявили replay команды другого аккаунта, неверный HTTPS deep link и тихую
   потерю51-й команды. Это immutable73482a3, не current web. Текущий compatible
   native package/API и OS/device/push/store acceptance не подтверждены.
